# Feature matrix

Every command-line option of **yt-dlp 2026.10.26** (this fork's `yt_dlp/options.py`) and where it lives in the Dubdeck desktop app.

This file is generated by `desktop/scripts/gen-matrix.ts` from the engine's own parser, so it cannot fall out of step with the code. Regenerate it after changing options:

```
cd desktop
npm run gen          # re-reads the engine options
npm run parity       # tests every flag against the real engine
npx tsx scripts/gen-matrix.ts
```

Coverage of documented options: **250 of 250 (100%)** have a dedicated, labelled control with a plain-English explanation.

### How parity is tested

`desktop/scripts/parity.ts` builds the arguments each control produces, using the same code the app uses to start downloads, and feeds them to yt-dlp's real `parse_options()` (`scripts/parity_check.py`). A flag passes when the engine accepts it **and** its resulting settings differ from a run without it. "Off" and "reset" flags are checked against a run that first sets the opposite. `--help` and `--version` exit the parser, so they are run as real engine commands. Hidden flags are passed through the *Extra arguments* path and must be accepted.

Beyond parsing, `desktop/test/wrapper.test.ts` runs real downloads through the job queue (video, audio extraction, playlist, broken link, invalid option, pause/resume, cancel, print-only, parallel limit, crash recovery, secret redaction), and a manual pass downloaded real media from archive.org with the packaged app.

### Where things are

- **Advanced › …**: the *Advanced* tab of New download (and of a preset, and of Settings › *Options for every download*). Every option shows its flags, a tooltip, a reset button, and appears in the live command preview.
- **Simple › …**: the *Simple* tab writes ordinary engine options. Advanced values override them, and the Simple tab says when that happens.
- **Engine › …**: one-off commands that do not download (`--list-extractors`, `--rm-cache-dir`, …) and updating.
- **Extra arguments**: the last entry in the Advanced list; passed to the engine verbatim, checked for unknown flags before starting.

## What could not be supported as-is, and why

Nothing is missing. A few options behave differently or have no visible effect because the app is not a terminal:

- **Interactive prompts.** Given `--username` without `--password` (or the TV-provider pair), the command-line engine asks for the password in the terminal; with no terminal it crashes. The app checks for this before starting and asks you to fill in both fields. If it slips through anyway (for example from an imported config) the failure is explained as "The engine wanted to ask a question".
- **`--batch-file -` (read links from standard input).** There is no standard input in the app; the app stops with an explanation before starting. Use a file, or paste the links into the Links box.
- **`--console-title`, `--bidi-workaround`, `--color`, `--newline`, `--progress`, `--quiet`, `--no-warnings`.** These change how a terminal shows output. They are passed to the engine unchanged, but the app shows progress from its own instrumentation, so their effect is limited to the log. If you set `--progress-template download:…` yourself, the app keeps your template and shows activity without a percentage.
- **`-U` / `--update-to` on a source checkout.** The engine refuses to update itself when it runs from source (development mode). Installed copies run a binary and can use it; the app's own updater is the recommended path either way.
- **`--help`.** Shown as text in Engine › Engine commands. The app's own help explains the same things in plain language.

Platform notes: Linux installers are built and tested here. Windows and macOS installers are produced by the GitHub Actions workflow (`.github/workflows/desktop.yml`) because they must be built on those systems. They are unsigned until signing certificates are added, so the first launch shows the usual "unidentified developer" warning.
